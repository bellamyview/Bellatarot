# 貝拉神秘魔法屋 · 塔羅牌網站

純靜態網站（HTML + CSS + JS，無需任何建置流程），共 80 個檔案：

- `index.html` — 網站主程式（結構、樣式、互動邏輯都在這一份檔案裡）
- `data.json` — 78 張牌的名稱、正逆位關鍵字、牌義說明、愛情/事業/財運/健康解讀
- `images/` — 78 張塔羅牌圖片（依 `data.json` 的 `image` 欄位命名）

## 上傳到 GitHub（網頁上傳）

1. 到 GitHub 建立一個新的 repository（例如 `bella-tarot`）。
2. 進入該 repo，點選「Add file → Upload files」。
3. 把這個資料夾裡的 **所有檔案與 `images` 資料夾** 一起拖曳上傳（共 80 個檔案，未超過 GitHub 網頁單次上傳的 100 個檔案限制）。
4. 送出 commit。

## 部署到 Vercel

1. 到 [vercel.com](https://vercel.com) 用 GitHub 帳號登入。
2. 「Add New → Project」，選擇剛剛的 repo。
3. Framework Preset 選 **Other**（不需要 Build Command，Output Directory 留空或填 `.` 即可，因為這是純靜態網站）。
4. 點 Deploy，等待完成即可拿到網址。

之後如果要更新牌義文字，只要編輯 `data.json`；要換圖片，只要替換 `images/` 裡對應檔名的圖片，重新 commit 到 GitHub，Vercel 會自動重新部署。

## 占卜功能

首頁新增「開始占卜」入口，流程為：選擇問題面向（愛情/事業/財運/健康）→ 在心中默念問題後按下抽卓 → 隨機顯示一張牌（正位或逆位）。逆位時圖片會直接以 CSS 旋轉 180 度顯示，所以不需要額外準備 156 張圖片，78 張原圖就足夠。

- 已內建避開 **17:00–19:00** 與 **23:00–01:00** 這兩個時段，該時段會顯示提示訊息、暫停抽卡按鈕（判斷依據是使用者裝置的本機時間）。
- 每次抽卡結果都會顯示提醒文字，告知同一個問題建議間隔至少一週再問；若瀏覽器偵測到使用者在 7 天內問過同一面向，會額外顯示提醒（資料存在使用者瀏覽器的 localStorage，僅供友善提醒，不會強制封鎖）。

### 抽卡機率的建議

- **每張牌被抽中的機率完全相同**：78 張牌，每張 1/78（約 1.28%），程式沒有對任何牌做加權，這是塔羅占卜可信度的基礎——使用者才會相信結果是「命運決定」而不是系統設計過的。
- **正位／逆位目前設定為 45% 逆位、55% 正位**（程式碼中的 `REVERSED_PROBABILITY = 0.45`，是一個獨立常數，之後想調整只要改這個數字）。這是業界常見的兩種做法之一：
  - **50 / 50**：邏輯最單純、最容易對使用者解釋「完全公平」。
  - **35–45% 逆位**：模擬實體牌卡的洗牌習慣——一副新牌通常全部正位，洗牌次數不夠多時逆位機率會略低於一半，很多實體占卜師也是抓這個區間，讀起來更貼近「真實洗牌」的體感。
  - 不建議把逆位機率壓得更低（例如 10-20%），逆位的解讀是塔羅完整體系的一半，太少會讓使用者長期只看到正位、失去逆位牌義的參考價值。
- **亂數來源**使用瀏覽器原生的 `crypto.getRandomValues`（比 `Math.random()` 亂數品質更好、更不可預測），而不是自行設計的演算法，避免有心人分析出規律。
- 刻意 **沒有做「重抽拿更好結果」的機制**（按一次只出一張，要再抽必須整個流程重來），這樣才符合「同一問題間隔一週」的精神，也維持占卜本身的公信力。

## 關於 Firebase（在線人數統計）

首頁最上方的「目前有 X 人正在占卜」，是用 **Firebase Realtime Database 的免費 Spark 方案** 做的即時連線人數統計（每人連上網站時寫入一筆連線紀錄，離線時自動移除）。步驟：

1. 到 [Firebase Console](https://console.firebase.google.com) 建立一個新專案（免費）。
2. 左側選單「Build → Authentication」→ 啟用登入方式 **匿名（Anonymous）**。
3. 左側選單「Build → Realtime Database」→ 建立資料庫（地區建議選離你的使用者最近的，例如 `asia-southeast1`），一開始先選「以鎖定模式啟動」也沒關係，等一下會貼規則進去。
4. 進「規則 Rules」分頁，貼上：
   ```json
   {
     "rules": {
       "presence": {
         ".read": true,
         "$uid": {
           ".write": "auth != null && auth.uid === $uid",
           ".validate": "newData.isBoolean()"
         }
       }
     }
   }
   ```
   這個規則只允許「已登入（含匿名登入）的使用者，寫入屬於自己 uid 的那一筆」，其他人的連線資料無法被竄改，也沒有任何個資會被寫入資料庫。
5. 左側「專案設定 → 一般」，網頁應用程式那邊會有一段 `firebaseConfig` 物件（`apiKey`、`authDomain`、`databaseURL`、`projectId`…），把它整段貼到 `index.html` 裡搜尋 `YOUR_API_KEY` 的地方，取代掉裡面的預設佔位文字。
6. 重新部署（推回 GitHub，Vercel 會自動重新建置）即可看到即時人數。

**免費方案（Spark）額度**：Realtime Database 同時上限約 100 個連線、每月 1GB 下載流量，對一般個人網站綽綽有餘；若沒有填入自己的 `firebaseConfig`，這個橫幅會直接隱藏、不影響網站其他功能。
